# Integration matrix

Research date: 2026-10-28, updated 2026-10-29 for 0.2.0. Every row below was checked against the current official documentation
or source code of the service. Items that could not be confirmed are marked **UNVERIFIED** and the
implementation treats them defensively (tolerant parsing, feature detection, explicit errors).

| Service | Verified integration method | Required credentials | Available functionality (as implemented) | Limitations |
| --- | --- | --- | --- | --- |
| **Trakt** | Official REST API v2 (`https://api.trakt.tv`), OAuth 2 **device flow** on `https://auth.trakt.tv` | Admin registers one Trakt app → **Client ID** + **Client Secret**. Each user authorizes via a device code. Public lists need only the Client ID: every API call requires `trakt-api-key` (verified: 403 without it), and the web app `app.trakt.tv` is a client-side SPA with no server-rendered list data, so a link cannot be read without a Client ID. | Watchlist and lists in rank order with movies, shows, **seasons and episodes** (`/sync/watchlist` and `/lists/{id}/items`, `extended=full` for runtimes), the user's own lists, liked lists, any **public list** by URL (`trakt.tv/users/{user}/lists/{slug}` or `trakt.tv/lists/{id}`) without a Trakt sign-in, list search, trending and popular lists. Automatic, paginated sync. | Rate limit 500 GET requests per 5 minutes (per user or per client+IP), 1 POST per second. Page size is capped at 250. Access tokens are short-lived (use `expires_in`, currently about 24 h) and refresh tokens are **single use**. Free Trakt accounts can connect only two community apps. Apps unused for 30 days are deleted automatically. Attribution is required. Trakt images must be cached and must not be hotlinked, so JellyWatcher uses TMDb artwork instead. |
| **Letterboxd** | **No usable API.** The official API is "by request only" and explicitly not granted "for private or personal projects". Supported alternatives: (1) **upload** of the user's own export ZIP or list CSV; (2) the user's public **RSS** feed (`letterboxd.com/{user}/rss/`) | Upload: none. RSS: Letterboxd username (public profile). | Import of the watchlist, watched films and lists from the account export ZIP; import of a single exported list CSV. Optional RSS "Recent diary" list, refreshed automatically: the last ~50 diary entries with `tmdb:movieId`, watched date and rating. | Uploads are a manual refresh: re-upload to update. Export CSVs contain only title, year and Letterboxd URI, so titles are matched through TMDb by title and year, and uncertain matches go to a review queue. Letterboxd has no watchlist RSS (it returns 404). ToS §6.8 and §6.11 prohibit scraping and exporting other members' content, so other members' public lists are **unsupported**. Films only. |
| **IMDb** | (1) **Public lists by link** through IMDb's public GraphQL endpoint `POST https://api.graphql.imdb.com/` (used by imdb.com itself; verified 2026-10-29: no key, needs an `x-imdb-client-name` header, `list(id)` returns items in list order with cursor paging, private lists return `FORBIDDEN`). (2) **Upload** of the CSV that IMDb's "Export" button produces, for watchlists and private lists. The website itself serves a bot challenge (WAF) and is never fetched. | None. | Links: any public list (`imdb.com/list/ls…`, locale prefixes like `/de/`), in list order, with episodes mapped to their series and season/episode number, runtimes, series episode/season counts; synced automatically. Uploads: watchlist, lists and ratings; `Const` (`tt…`) is resolved to TMDb exactly; Title Type is mapped to movie or TV. | The GraphQL endpoint is undocumented; IMDb permits only limited non-commercial use of its data (shown in every response). Watchlists are private by default, so use the CSV. CSV uploads skip episodes (no series column) and refresh only on re-upload. The CSV columns are **UNVERIFIED** for the newest export format, so the parser accepts several column name variants. |
| **Seerr** (≥ v3; Overseerr/Jellyseerr API-compatible) | REST API `{url}/api/v1`, header `X-Api-Key`. Requests are made on behalf of a mapped Seerr user with `X-API-User: <seerrUserId>`, so that user's permissions, quotas and approval rules apply. | Seerr **URL** + **API key** (Settings → General). The API key grants admin rights; it is stored encrypted server-side only. | Connection test (`/status`, `/auth/me`), user list for mapping (`/user`), search including `imdb:`/`tmdb:` prefixes (`/search`), media status (`/movie/{tmdbId}`, `/tv/{tmdbId}` → `mediaInfo`), request creation (`POST /request`), request status (`GET /request/{id}`, `GET /request`). Optional webhook from Seerr triggers immediate re-sync. | No push without the webhook, so status is polled. Requesting fails with 403 (no permission, quota, blocklisted), 409 (duplicate) or 202 (no seasons available); each is shown with a specific message. If Seerr's CSRF protection is enabled, POSTs with an API key may fail (**UNVERIFIED**); this is detected and reported. |
| **Jellyfin** (12.x; 10.10/10.11 compatible) | REST API with header `Authorization: MediaBrowser Token="…", Client=…, Device=…, DeviceId=…, Version=…` (the legacy `X-Emby-Token` and `api_key` are disabled in 12.0) | Jellyfin **URL** + **API key** (Dashboard → API Keys). Users link their own Jellyfin account by signing in with Jellyfin credentials (`/Users/AuthenticateByName`), which proves ownership; JellyWatcher keeps only the user ID. | Connection test (`/System/Info/Public`, `/System/Info`). Library index via paginated `GET /Items` (Movie, Series) with `ProviderIds`. Per-user played state, progress and unplayed episode counts via `GET /Items?userId=…&enableUserData=true`. Episodes of listed series via `GET /Shows/{id}/Episodes?userId=…` (presence, runtime, played state; re-read only when the series' user data changes). Poster proxy and deep links. Optional "Sign in with Jellyfin" for JellyWatcher accounts. | No server-side filter by TMDb ID (`AnyProviderIdEquals` does not exist), so the full library is indexed and matched locally. Items without provider IDs fall back to title and year matching. Series progress counts are episode based. **Read-only**: JellyWatcher never writes played state. |
| **TMDb** (optional but recommended) | REST API v3, `Authorization: Bearer <API Read Access Token>` | TMDb **API Read Access Token** (free, themoviedb.org → Settings → API) | Metadata enrichment (poster, backdrop, synopsis, genres, runtime), external ID resolution (`/find/{imdb_id}`), title and year search for unmatched imports, runtimes and season/episode counts for watch time. | About 40 requests per second; handle 429 responses. Non-commercial use with attribution. **Fallback:** without a TMDb token, JellyWatcher uses Seerr's TMDb proxy (`/search`, `/movie/{id}`, `/tv/{id}`) for the same data. |

## What is explicitly unsupported (and why)

| Requested capability | Status | Reason / alternative |
| --- | --- | --- |
| Automatic Letterboxd watchlist or list sync | Unsupported | The API is closed to personal projects, there is no watchlist RSS, and the ToS forbids scraping. Alternative: upload the export ZIP or CSV again; the RSS diary syncs automatically. |
| Importing other members' Letterboxd lists | Unsupported | ToS §6.8 ("must not export any content … except your own"). |
| Automatic IMDb watchlist sync | Unsupported | Watchlists are private by default and need sign-in. Alternative: CSV upload, or make it public and add it by link. |
| Discover / search for new titles | Removed in 0.2.0 | Seerr already does this; JellyWatcher focuses on lists. |
| Writing watched state back to Jellyfin, Trakt or Letterboxd | Not implemented by design | One-way sync avoids conflicting state loops. Jellyfin is authoritative for viewing state. |
| Trakt watched-history import | Not implemented | Jellyfin is the source of truth for viewing progress; mixing a second watched source would create conflicts. The adapter design allows adding it later. |
| Trakt "link-only" (`privacy=link`) lists | **UNVERIFIED** | No documented endpoint for share-hash lists. Only public lists and lists owned by the user are supported. |

## Source of truth per status

| Status | Authority | Fallback |
| --- | --- | --- |
| List membership | The source service (Trakt API, uploaded file, RSS) | none |
| Title identity and metadata | TMDb (direct, or proxied through Seerr) | Source-provided title and year |
| Request state | Seerr (`MediaRequest.status`) | none; shown as "Unknown" when not synced |
| Library availability | Jellyfin (`/Items` index) | Seerr `mediaInfo.status`, labelled "reported by Seerr" |
| Viewing progress | Jellyfin user data for the linked Jellyfin user | Remembered history (`watch_history`, `watched_episodes`) once a title leaves the library, e.g. deleted in Seerr/Sonarr/Radarr after watching |
