# Integration matrix

Research date: 2026-10-28, updated 2026-10-29 for 0.3.0 (Jellyfin Quick Connect and API-key endpoints checked against the Jellyfin 12.4.0 OpenAPI spec) and for 0.4.0 (Letterboxd list pages, TMDb lists, MyAnimeList, AniList, MDBList and the anime id mapping checked against the live services; the Simkl export shape follows its documented API). Every row below was checked against the current official documentation
or source code of the service. Items that could not be confirmed are marked **UNVERIFIED** and the
implementation treats them defensively (tolerant parsing, feature detection, explicit errors).

| Service | Verified integration method | Required credentials | Available functionality (as implemented) | Limitations |
| --- | --- | --- | --- | --- |
| **Trakt** | Official REST API v2 (`https://api.trakt.tv`), OAuth 2 **device flow** on `https://auth.trakt.tv` | Admin registers one Trakt app → **Client ID** + **Client Secret**. Each user authorizes via a device code. Public lists need only the Client ID: every API call requires `trakt-api-key` (verified: 403 without it), and the web app `app.trakt.tv` is a client-side SPA with no server-rendered list data, so a link cannot be read without a Client ID. | Watchlist and lists in rank order with movies, shows, **seasons and episodes** (`/sync/watchlist` and `/lists/{id}/items`, `extended=full` for runtimes), the user's own lists, liked lists, any **public list** by URL (`trakt.tv/users/{user}/lists/{slug}` or `trakt.tv/lists/{id}`) without a Trakt sign-in, list search, trending and popular lists. Automatic, paginated sync. | Rate limit 500 GET requests per 5 minutes (per user or per client+IP), 1 POST per second. Page size is capped at 250. Access tokens are short-lived (use `expires_in`, currently about 24 h) and refresh tokens are **single use**. Free Trakt accounts can connect only two community apps. Apps unused for 30 days are deleted automatically. Attribution is required. Trakt images must be cached and must not be hotlinked, so JellyWatcher uses TMDb artwork instead. |
| **Letterboxd** | **No usable API.** The official API is "by request only" and explicitly not granted "for private or personal projects". Used instead: (1) **public list and watchlist pages** by link (`letterboxd.com/{user}/list/{slug}/`, `/{user}/watchlist/`, `boxd.it/…` short links), read like a browser shows them (verified 2026-10-29: films carry `data-item-slug` and `data-item-name="Title (Year)"`, 100 per page, `/page/N/`); (2) **upload** of the user's own export ZIP or list CSV; (3) the user's public **RSS** feed (`letterboxd.com/{user}/rss/`) | Links: none. Upload: none. RSS: Letterboxd username (public profile). | Links: any public list or watchlist in its order, every page, synced automatically (one page per 400 ms). Your own watchlist link replaces an uploaded watchlist. Uploads: watchlist and lists from the account export ZIP, or a single list CSV. Optional RSS "Recent diary" list: the last ~50 diary entries with `tmdb:movieId`, watched date and rating. | Pages and exports carry only title and year, so titles are matched through TMDb by title and year; uncertain matches go to the review queue. Private lists only work through an export. The page markup is not an API and can change; the JSON endpoints Letterboxd's own pages use sit behind a Cloudflare challenge and are not used. Letterboxd's terms (§6.8, §6.11) restrict automated access and exporting other members' content: links are meant for personal use of lists you can see in your browser. Films only. |
| **IMDb** | (1) **Public lists by link** through IMDb's public GraphQL endpoint `POST https://api.graphql.imdb.com/` (used by imdb.com itself; verified 2026-10-29: no key, needs an `x-imdb-client-name` header, `list(id)` returns items in list order with cursor paging, private lists return `FORBIDDEN`). (2) **Upload** of the CSV that IMDb's "Export" button produces, for watchlists and private lists. The website itself serves a bot challenge (WAF) and is never fetched. | None. | Links: any public list (`imdb.com/list/ls…`, locale prefixes like `/de/`), in list order, with episodes mapped to their series and season/episode number, runtimes, series episode/season counts; synced automatically. Uploads: watchlist, lists and ratings; `Const` (`tt…`) is resolved to TMDb exactly; Title Type is mapped to movie or TV. | The GraphQL endpoint is undocumented; IMDb permits only limited non-commercial use of its data (shown in every response). Watchlists are private by default, so use the CSV. CSV uploads skip episodes (no series column) and refresh only on re-upload. The CSV columns are **UNVERIFIED** for the newest export format, so the parser accepts several column name variants. |
| **Seerr** (≥ v3; Overseerr/Jellyseerr API-compatible) | REST API `{url}/api/v1`, header `X-Api-Key`. Requests are made on behalf of a mapped Seerr user with `X-API-User: <seerrUserId>`, so that user's permissions, quotas and approval rules apply. | Seerr **URL** + **API key** (Settings → General). The API key grants admin rights; it is stored encrypted server-side only. | Connection test (`/status`, `/auth/me`), user list for mapping (`/user`), search including `imdb:`/`tmdb:` prefixes (`/search`), media status (`/movie/{tmdbId}`, `/tv/{tmdbId}` → `mediaInfo`), request creation (`POST /request`), request status (`GET /request/{id}`, `GET /request`). Optional webhook from Seerr triggers immediate re-sync. | No push without the webhook, so status is polled. Requesting fails with 403 (no permission, quota, blocklisted), 409 (duplicate) or 202 (no seasons available); each is shown with a specific message. If Seerr's CSRF protection is enabled, POSTs with an API key may fail (**UNVERIFIED**); this is detected and reported. |
| **Jellyfin** (12.x; 10.10/10.11 compatible) | REST API with header `Authorization: MediaBrowser Token="…", Client=…, Device=…, DeviceId=…, Version=…` (the legacy `X-Emby-Token` and `api_key` are disabled in 12.0) | Jellyfin **URL** + **API key** (Dashboard → API Keys). Users link their own Jellyfin account by signing in with Jellyfin credentials (`/Users/AuthenticateByName`), which proves ownership; JellyWatcher keeps only the user ID. | Connection test (`/System/Info/Public`, `/System/Info`). Library index via paginated `GET /Items` (Movie, Series) with `ProviderIds`. Per-user played state, progress and unplayed episode counts via `GET /Items?userId=…&enableUserData=true`. Episodes of listed series via `GET /Shows/{id}/Episodes?userId=…` (presence, runtime, played state; re-read only when the series' user data changes). Poster proxy and deep links. Sign-in with Jellyfin (`/Users/AuthenticateByName`) and **Quick Connect** (`GET /QuickConnect/Enabled`, `POST /QuickConnect/Initiate`, `GET /QuickConnect/Connect?secret=`, `POST /Users/AuthenticateWithQuickConnect`); the session is ended immediately (`/Sessions/Logout`). Guided setup like Seerr: an administrator signs in and JellyWatcher creates its own key (`POST /Auth/Keys?app=JellyWatcher`, then `GET /Auth/Keys`). | No server-side filter by TMDb ID (`AnyProviderIdEquals` does not exist), so the full library is indexed and matched locally. Items without provider IDs fall back to title and year matching. Series progress counts are episode based. **Read-only**: JellyWatcher never writes played state. |
| **TMDb** (optional but recommended) | REST API v3, `Authorization: Bearer <API Read Access Token>`; API v4 `GET /4/list/{id}?page=N` for lists (same token) | TMDb **API Read Access Token** (free, themoviedb.org → Settings → API) | Metadata enrichment (poster, backdrop, synopsis, genres, runtime, season air dates), external ID resolution (`/find/{imdb_id}`), title and year search for unmatched imports, runtimes and season/episode counts for watch time. **Public lists by link** (`themoviedb.org/list/{id}`) in the list's own order with comments, synced automatically. CSV uploads with a TMDb ID column. | About 40 requests per second; handle 429 responses. Non-commercial use with attribution. **Fallback:** without a TMDb token, JellyWatcher uses Seerr's TMDb proxy (`/search`, `/movie/{id}`, `/tv/{id}`) for the same data, but Seerr cannot read TMDb lists, so list links need the token. Private lists, watchlists and favorites need a TMDb user session and are not supported. |
| **MyAnimeList** | (1) **Public anime lists by link**: the JSON the list page loads, `GET https://myanimelist.net/animelist/{user}/load.json?status={n}&offset={k}` (verified 2026-10-29: no client id, 300 entries per page, 400 for private or unknown lists; status 1 watching, 2 completed, 3 on hold, 4 dropped, 6 plan to watch, 7 all). (2) **Upload** of the XML export (Profile › Export Lists, `.xml.gz`). The official API v2 needs a registered client id and is not used. | None. | Links: the list chosen by `?status=` (Plan to Watch by default), synced automatically. Uploads: Watching, Plan to Watch and On Hold, one list each. Anime are mapped to TMDb (see *Anime id mapping*). | `load.json` is undocumented and can change. Manga lists are unsupported. Completed and dropped entries in exports are skipped (history, not watchlists). |
| **AniList** | Official public **GraphQL API** `POST https://graphql.anilist.co`, `MediaListCollection(userName, type: ANIME)` (verified 2026-10-29: no key for public profiles; private profiles return `Private User`). | None. | Links: `anilist.co/user/{name}/animelist[/{list}]`; a status list (Planning by default, including AniList's per-format splits) or a custom list by name; MAL ids, format, episodes and minutes per episode are read. Synced automatically. Uploads: MyAnimeList-format XML. | Rate limit 90 requests per minute (30 while degraded); one request per sync. AniList has no export of its own. |
| **Simkl** | **Upload** of the user's export (CSV, or the JSON backup shaped like the API's `/sync/all-items`, or the ZIP). | None. | Plan to Watch, Watching and On Hold become one list each; entries use the TMDb, IMDb or TVDB ids Simkl includes; anime use the anime id mapping. | Simkl's API returns lists only to apps a person signs in to (OAuth/PIN with a registered client id), so Simkl links cannot be read. The export format is **UNVERIFIED** in detail; the parser accepts common column names and both export shapes. Re-upload to update. |
| **MDBList** | **Public list JSON feed**: `{list url}/json` (verified 2026-10-29: no API key; array in list order with `id` = TMDb id, `imdb_id`, `tvdbid`, `mediatype` movie/show, `release_year`). The list name is read from the list page's `og:title`. | None. | Links: `mdblist.com/lists/{user}/{list}`, static and dynamic lists, matched exactly by TMDb id, synced automatically. Uploads: the list's CSV export. | Private lists need the account's API key and are not supported by link; upload their CSV instead. |
| **Anime id mapping** | Community-maintained [Fribb/anime-lists](https://github.com/Fribb/anime-lists) `anime-list-full.json` (verified 2026-10-29: `mal_id`, `anilist_id`, `simkl_id`, `themoviedb_id {tv}` or `{movie: []}`, `season.tmdb`, `episode_offset.tmdb`, `tvdb_id`, `imdb_id []`). | None. | Downloaded on first anime import, reduced and cached at `/data/cache/anime-ids.json`, refreshed weekly (a stale copy is used when GitHub is unreachable). Later seasons and split cours become **season entries** of the TMDb show, named after the anime entry; anime movies map to TMDb movies. | Community data: gaps and mistakes are possible; unmapped titles fall back to title search. TMDb season numbering for anime can differ from how a list splits them. |

## What is explicitly unsupported (and why)

| Requested capability | Status | Reason / alternative |
| --- | --- | --- |
| Private Letterboxd lists by link | Unsupported | Only public pages can be read without signing in. Alternative: upload the export ZIP or the list's CSV. |
| Simkl lists by link | Unsupported | Simkl shares lists only with signed-in apps. Alternative: upload the Simkl export. |
| TMDb watchlists and favorites | Unsupported | They need a TMDb user session. Alternative: put the titles in a public TMDb list, or export a CSV. |
| Automatic IMDb watchlist sync | Unsupported | Watchlists are private by default and need sign-in. Alternative: CSV upload, or make it public and add it by link. |
| Discover / search for new titles | Back in 0.3.0, for local lists only | Search, trending and popular titles (TMDb, or Seerr's `/discover/*` and `/search`) to add to your own lists. Requests still go through Seerr. |
| Writing watched state back to Jellyfin, Trakt or Letterboxd | Not implemented by design | One-way sync avoids conflicting state loops. Jellyfin is authoritative for viewing state. |
| Trakt watched-history import | Not implemented | Jellyfin is the source of truth for viewing progress; mixing a second watched source would create conflicts. The adapter design allows adding it later. |
| Trakt "link-only" (`privacy=link`) lists | **UNVERIFIED** | No documented endpoint for share-hash lists. Only public lists and lists owned by the user are supported. |

## Source of truth per status

| Status | Authority | Fallback |
| --- | --- | --- |
| List membership | The source service (API, public list page or feed, uploaded file, RSS) | none |
| "Not watching" | The person (`skipped_entries`); a title that is watched is never shown as skipped | none |
| Title identity and metadata | TMDb (direct, or proxied through Seerr) | Source-provided title and year |
| Request state | Seerr (`MediaRequest.status`) | none; shown as "Unknown" when not synced |
| Library availability | Jellyfin (`/Items` index) | Seerr `mediaInfo.status`, labelled "reported by Seerr" |
| Viewing progress | Jellyfin user data for the linked Jellyfin user | Remembered history (`watch_history`, `watched_episodes`) once a title leaves the library, e.g. deleted in Seerr/Sonarr/Radarr after watching |
